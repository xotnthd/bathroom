# AI 에이전트 행동 통제 및 안전 규칙 (AGENTS.md)

이 규칙은 AI가 소스 코드를 수정할 때 지켜야 할 **최우선 강제 사항**입니다. 어떤 상황에서도 아래 규칙을 우회하거나 자체적인 판단으로 무시해서는 안 됩니다.

## 1. 소스 코드 수정의 대원칙 (Targeted Modification Only)
- 소스 수정은 **문제가 발생한 부분에 대해서만 최우선적으로 핀포인트 수정**한다.
- 파일 전체를 임의로 뜯어고치거나 불필요하게 구조를 바꾸는 행위는 절대 금지한다.
- 기존에 정상적으로 동작하고 문제가 되지 않았던 부분은 **절대 건드리지 않는 것**을 기본 원칙으로 한다.

## 2. 자의적이고 광범위한 스크립트 기반 대량 수정 절대 금지 (Bulk Edit Prohibition)
- 사용자가 명시적으로 수정을 요청하지 않은 "잘 돌아가던 소스 코드"는 절대 임의로 뜯어고치지 않는다.
- 정규식(Regex)을 이용한 Node.js나 Bash 스크립트로 여러 파일을 일괄 수정하는 행위(Bulk Edit)를 절대 금지한다.
- 인코딩 오류, 오타 등 단순 문제라도 전체 파일에 대한 터미널 스크립트 치환을 시도하지 않고, 내장 편집 도구(replace_file_content)를 활용하여 정밀하게 부분 수정한다.

## 3. 기능 개발 전 검토 및 공통 영역 우선 확인 (Feature Review & Common Structure)
- 각 메뉴 및 기능별로 사용자가 요청한 내용을 **적용하기 전에 먼저 철저히 검토**한다.
- 해당 기능이 시스템 전체에 공통적으로 적용되어야 하는 부분인지 우선 확인하며, 개별 소스에 개별적으로 처리되는 구조(Spaghetti Code)를 만들지 않는다.
- 작업 완료 시, 사용자가 세세한 구현 내용을 파악하고 검토할 수 있도록 항상 관련 문서 및 진행 상황을 **최신화(업데이트) 처리한 후 요청을 마무리**한다.

## 4. 작업 일괄 처리 및 승인 대기 최소화 (Batch Processing)
- 계획을 수립할 때, 사용자가 터미널 스크립트를 매번 승인(Allow)하느라 시간을 낭비하지 않도록 불필요한 명령어 호출을 최소화한다.
- 여러 작업이 필요할 때는 개별 작업마다 승인을 받지 말고, 한 번에 일괄(Batch) 진행할 수 있도록 구조화하여 사용자 개입을 최소화한다.

## 5. 데이터베이스 스키마 현행화 및 자동 참조 (DB Schema Tracking)
- 데이터베이스 테이블의 컬럼 추가, 제거, 변경 사항이 발생할 경우, **반드시 `db_schema.md` 파일을 즉시 최신화**한다.
- AI는 로직이나 쿼리를 작성/수정하기 전, 항상 `db_schema.md`를 읽고 현재 데이터베이스 스키마 구조를 완벽히 인지한 상태에서 작업한다.
- 사용자가 "스키마 최신화해라"라고 명령할 경우 즉각적으로 구조를 재검토하여 문서에 반영한다.

## 6. 토큰 낭비 및 에러 은폐 엄격 금지
- 본인의 수정으로 인해 빌드 에러 등 문제가 발생했을 경우, 이를 억지로 덮으려고 무리하게 코드를 추가하며 토큰을 낭비하지 않는다.
- 즉시 작업을 중지하고 문제 상황을 사용자에게 명확하게 보고한 뒤 지시를 기다린다.

## 7. 하드코딩 값 발견 시 공통코드화 제안 (Common Code Extraction)
- 소스 코드를 수정하다가 화면 단(JSX)에 특정 상태값이나 선택 옵션이 하드코딩 되어있는 것을 발견할 경우, **우선 기존 코드에 오류가 나지 않도록 조치**한다.
- 그 후, 하드코딩된 값을 `CommonCodePicker` 등의 공통 컴포넌트로 활용할 수 있도록 **해당 코드 값을 공통코드 테이블에 INSERT 하는 제안과 SQL 스크립트를 사용자에게 선제적으로 제공**한다.

## 8. 관리자 화면 기본 구조 통일 (Admin UI Standard)
- 관리자 화면의 모든 페이지는 `PopupManage` 모듈에 적용된 UI/UX 형태를 **기본 구조**로 삼는다.
- 세부 기준: 
  1. 리스트와 등록/수정 모달 분리 구조
  2. 표(Table) 형식의 테두리가 있는 명확한 모달 폼 레이아웃 (`.admin-form-row`, `.admin-form-label` 등)
  3. 상단 조회 영역의 검색 조건은 변경 즉시 반영(auto-trigger)되거나 명확한 조회 버튼 구비
  4. 수정 모드 진입 시 시스템 기준 등 핵심 값의 제어 및 상태 값(노출 기간 등)에 따른 Read-Only 처리 로직 적용
- 향후 신규 페이지 작성 및 기존 페이지 리팩토링 시, 반드시 이 기본 구조와 스타일 클래스 패턴을 동일하게 적용하여 전체 통일성을 유지한다.
